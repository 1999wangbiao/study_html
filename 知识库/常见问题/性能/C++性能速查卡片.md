# C++ 性能速查卡片

> 配套：[C++性能认知-从内存布局到工程实践](./C++性能认知-从内存布局到工程实践.md)  
> 用法：每张卡片独立可读，写代码前扫一眼对应主题即可。

## 卡片 00：总原则

| 项目 | 内容 |
|------|------|
| **一句话** | 先问「根本问题是什么、愿意付什么代价」，再选实现。 |
| **存储阶梯** | 编译期 → 栈 → 静态区 → 堆 → 外存 |
| **调用阶梯** | 内联 < 直接调用 < 虚调用 < `std::function` |
| **四条铁律** | ① 存储层次决定代价 ② 抽象不免费但可零开销 ③ 选型 > 优化 ④ 大 O ≠ 实测 |

✅ 先做对，再在正确前提下优化  
❌ 不要过早优化，也不要把理论当教条

## 一、存储与内存

### 卡片 01：constexpr

| 项目 | 内容 |
|------|------|
| **代价** | 零（编译期嵌入二进制） |
| **vs const** | `const` 只承诺不修改；`constexpr` 强制编译期求值 |
| **适用** | 常量表、编译期可确定的计算 |

```cpp
const int a = strlen("hello");  // 运行时
constexpr int b = 5;            // 编译期
```

✅ 能在编译期算的，不要留到运行时  
❌ 不要把运行时数据硬塞给 `constexpr`

---

### 卡片 02：栈 vs 堆

| 项目 | 内容 |
|------|------|
| **栈** | ~1 条指令（移动栈指针） |
| **堆** | 数百条指令 + 可能锁竞争 + 碎片 |
| **热路径** | 优先栈；`std::array`、SSO 都是同一思路 |

```cpp
int arr[256];           // 栈：快
int* arr = new int[256]; // 堆：慢，还要 delete
```

✅ 固定大小、短生命周期 → 栈  
❌ 每帧 / 每次按键在热路径 `new`/`delete`

---

### 卡片 03：全局变量

| 项目 | 内容 |
|------|------|
| **隐性代价** | SIOF、阻碍优化、线程安全 |
| **SIOF** | 跨编译单元全局初始化顺序未定义 |
| **替代** | Meyers 单例（局部 static） |

✅ 需要延迟初始化 → Meyers 单例  
❌ 跨文件依赖全局变量初始化顺序

---

### 卡片 04：单例选型

| 实现 | 运行时开销 | 适合场景 |
|------|-----------|---------|
| Meyers（局部 static） | 每次原子读（~<1ns） | 默认首选，线程安全 |
| 饿汉式（全局 static） | 零 | 构造轻、热路径极高频 |

✅ 构造重 → Meyers，避免拖慢启动  
❌ 热路径百万次调用却忽略原子读累积

---

### 卡片 05：结构体对齐

| 项目 | 内容 |
|------|------|
| **原则** | 成员按大小降序排列，减小 padding |
| **缓存** | `alignas(64)` 对齐缓存行 |
| **慎用** | `#pragma pack`（除序列化等特殊场景） |

```cpp
struct Bad  { char a; double b; char c; };  // 24B
struct Good { double b; char a; char c; };  // 16B
```

✅ 大量放入 `vector` 的结构体先优化布局  
❌ 为省几字节牺牲未对齐访问（可能崩溃）

## 二、对象与调用

### 卡片 06：Trivially Copyable

| 类型 | `vector` 行为 |
|------|--------------|
| `Point { int x, y; }` | 可 `memcpy`，快 |
| 含 `std::string` / 虚函数 | 逐成员构造/析构，慢 |

✅ 热点数据尽量 POD / trivial  
❌ 对非 trivial 类型 `memcpy`

---

### 卡片 07：虚函数

| 维度 | 代价 |
|------|------|
| 空间 | +vptr（64 位 8B），对象变大 |
| 时间 | 读 vptr → 读 vtable → 间接跳转 |
| 优化 | 无法内联（除非 devirtualize） |

✅ 编译期类型确定 → 模板 / CRTP / `final`  
❌ 热路径滥用虚函数做「方便的多态」

---

### 卡片 08：调用代价光谱

```
内联 ≈0  <  直接 ~1ns  <  虚调用 ~2-5ns  <  std::function ~5-15ns
```

| 机制 | 要点 |
|------|------|
| 内联 | `inline` 主要是 ODR；决定权在编译器 |
| LTO | 跨单元内联，链接变慢 |
| 模板回调 | 替代 `std::function`，可内联 |

```cpp
// 慢
void f(std::function<void(int)> cb);
// 快
template<typename F> void f(F cb);
```

✅ 热路径回调用模板  
❌ 过度 `__forceinline`（I-cache 压力）

---

### 卡片 09：CRTP

| 项目 | 内容 |
|------|------|
| **本质** | 编译期多态，`static_cast<Derived*>` 绑定 |
| **收益** | 零运行时分发，可内联 |
| **代价** | 编译时间、代码膨胀 |
| **WPS 例** | `KAtomVariety2` |

✅ 多态关系编译期可确定 → CRTP  
❌ 需要运行时通过基类指针分发 → 别硬上 CRTP

---

### 卡片 10：类型转换阶梯

```
static_cast  <  dynamic_cast  <  QueryInterface
  近零开销       RTTI 遍历        虚调用+GUID+AddRef
```

✅ 类型确定 → `static_cast`  
✅ 类型可枚举 → `enum + switch` / visitor  
❌ 循环里反复 `dynamic_cast` / `QueryInterface`（应缓存）

---

### 卡片 11：异常与 noexcept

| 维度 | 代价 |
|------|------|
| `/EH` 空间 | 二进制 +10%~30% |
| 抛出时间 | 比正常路径慢 10~100 倍 |
| `noexcept` | 影响 `vector` 扩容用 move 还是 copy |

✅ 罕见严重错误 → 异常  
✅ 移动构造标记 `noexcept`  
❌ 用异常做正常控制流  
❌ 性能敏感模块盲目开 `/EH`

## 三、智能指针

### 卡片 12：unique_ptr

| 项目 | 内容 |
|------|------|
| **代价** | 零，与裸指针同大小 |
| **deleter** | 无状态仿函数零开销；函数指针 deleter 大小翻倍 |

✅ 独占所有权默认首选  
❌ 函数指针 deleter 导致 `unique_ptr` 变胖

---

### 卡片 13：shared_ptr

| 项目 | 内容 |
|------|------|
| **代价** | 控制块 16~40B + 原子操作 + 可能两次堆分配 |
| **优化** | `make_shared` 合并分配 |
| **传参** | 传 `const&` 或裸指针，避免值传递 |

```cpp
void good(const std::shared_ptr<T>& p);  // 不改计数
void bad(std::shared_ptr<T> p);          // 原子 ++
```

✅ 真正需要共享所有权再用  
❌ 不需要共享却到处传 `shared_ptr` 值

---

### 卡片 14：ks_stdptr（WPS）

| 项目 | 内容 |
|------|------|
| **模型** | 侵入式引用计数，无独立控制块 |
| **场景** | COM / 跨 DLL |
| **陷阱** | `KS_NEW` 已持引用，赋值会双重 AddRef → 泄漏 |

```cpp
// 错
ks_stdptr<T> p = KS_NEW(T);
// 对
ks_stdptr<T> p; p.attach(KS_NEW(T));
```

✅ 接管已有引用用 `attach`，交出用 `detach`  
❌ `detach()` 后直接赋值给另一个 `ks_stdptr`（又 AddRef）

---

### 卡片 15：智能指针决策

```
独占？ → unique_ptr
共享 + COM？ → ks_stdptr
共享 + 非 COM？ → shared_ptr（make_shared）
需要弱引用？ → weak_ptr
```

## 四、字符串

### 卡片 16：SSO

| 实现 | sizeof | SSO 阈值 |
|------|--------|---------|
| MSVC / libstdc++ x64 | 32 | ≤15 字节 |
| libc++ x64 | 24 | ≤22 字节 |

**易忽略**：SSO 内 move ≈ copy（都是 memcpy 整个对象体）

✅ 短字符串自然享受零堆分配  
❌ 指望 move 优化 SSO 范围内的短串

---

### 卡片 17：编码

| 项目 | 内容 |
|------|------|
| **代价** | 编码转换是 CPU 密集型 |
| **WPS** | 内核 UTF-16，外部按需转 |
| **原则** | 统一内部编码，减少来回转换 |

✅ 层与层之间约定一种编码  
❌ 每个函数边界都做 UTF-8 ↔ UTF-16

---

### 卡片 18：string_view

| 项目 | 内容 |
|------|------|
| **代价** | 零拷贝（16B = ptr + size） |
| **限制** | 不拥有数据、不保证 `\0` 结尾 |
| **参数** | 只读字符串用最小语义类型（如 `PCWSTR`） |

✅ 只读参数 → `string_view` / `PCWSTR`  
❌ 把 `string_view` 存成长期成员  
❌ 直接传给要求 `\0` 结尾的 C API

---

### 卡片 19：字符串陷阱

| 陷阱 | 对策 |
|------|------|
| `a + b + c` 连锁临时对象 | `Format` / `reserve + append` |
| `std::move(const s)` | 实际是拷贝，编译器不警告 |
| `const ks_wstring&` 参数 | 改用 `PCWSTR` 等更小类型 |
| QString COW | 原子计数 + 意外深拷贝 + 缓存失效 |

## 五、容器

### 卡片 20：vector 优先

| 项目 | 内容 |
|------|------|
| **原因** | 连续内存，缓存预取友好 |
| **list** | 节点分散堆上，缓存不友好 |
| **实践** | 热路径小 vector 记得 `reserve` |

✅ 默认选 `vector`  
❌ 为中间插入 O(1) 盲目选 `list`（实测常更慢）

---

### 卡片 21：关联容器

| 场景 | 结论 |
|------|------|
| N < 几百 | `vector` 线性查找可能更快 |
| 哈希碰撞 | O(1) 退化为 O(n) |

**踩坑例**：`hash = row << 20 | col` → 同列低位相同 → 链表

✅ 哈希设计考虑真实数据分布  
❌ 只看大 O 不看常数因子和缓存

## 六、踩坑案例（9 张）

### 卡片 22：哈希退化

**现象**：哈希表变链表  
**根因**：行坐标编码高位，同列低位相同  
**对策**：按真实数据分布设计哈希

---

### 卡片 23：detach 与二次释放

**现象**：crash 或双重释放  
**根因**：资源转移未 `detach`，内外语义不一致  
**对策**：接管方释放，交出方 `detach`

---

### 卡片 24：detach 与泄漏

**现象**：静默泄漏  
**根因**：内部 `detach` 给调用方，调用方只读捕获未释放  
**对策**：文档化所有权转移契约

---

### 卡片 25：分支泄漏

**现象**：某路径对象永不释放  
**根因**：managed 参数在空分支未处理  
**对策**：RAII，所有分支自动释放

---

### 卡片 26：配对操作泄漏

**现象**：`begin`/`end` 不匹配  
**根因**：中间步骤失败提前退出  
**对策**：RAII 保护配对操作（作用域 guard）

---

### 卡片 27：宏副作用

**现象**：结果错误或多次执行  
**根因**：表达式作为宏参数被多次展开  
**对策**：宏参数用简单变量；能改 `constexpr`/函数就别用宏

---

### 卡片 28：迭代器偏移

**现象**：未定义行为 / 失效  
**根因**：链式 `it++ + n`  
**对策**：`it += n` 或 `std::advance`

---

### 卡片 29：临时对象野指针

**现象**：野指针访问  
**根因**：链式调用返回临时对象，指针指向已销毁对象  
**对策**：延长生命周期或立即拷贝到命名变量

---

### 卡片 30：包装类性能差

**现象**：同逻辑慢 30%  
**根因**：返回 `IUnknown` 包装 vs 原始对象，高频 AddRef/Release  
**对策**：热路径返回原始对象或缓存包装

## 七、一张表速览

| 机制 | 主要代价 | 优先替代 |
|------|---------|---------|
| 堆分配 | 高 + 锁 | 栈 / SSO / reserve |
| 虚函数 | vptr + 间接调用 | CRTP / 模板 / `final` |
| `std::function` | 擦除 + 堆 + 不内联 | 模板回调 |
| `dynamic_cast` | RTTI | `static_cast`（确定时） |
| `/EH` | 二进制膨胀 | 错误码 |
| `shared_ptr` | 原子 + 控制块 | `unique_ptr` / 传引用 |
| `unordered_map`（小 N） | 哈希常数大 | `vector` 线性查 |
| 编码转换 | CPU 密集 | 统一内部编码 |
