# 闭包（Closure）

闭包就是一个 **函数+它记住的外部变量** 的组合。

## 1. 基本示例：计数器

### 1.1 逐行拆解

```go
func outer() func() int {
    count := 0           // ① 局部变量，属于 outer 的栈帧
    return func() int {  // ② 返回一个匿名函数
        count++          // ③ 这个函数引用了 count
        return count
    }
}
```

关键：当 `outer()` 执行完毕后，`count` 按理应该被销毁。但因为返回的匿名函数**引用**了它，Go 编译器会把 `count` 从栈搬到堆上（逃逸分析），让它的生命周期跟着匿名函数走。

### 1.2 执行流程

```
counter := outer()    → 创建 count=0，返回闭包 A（捕获了 count）
counter()            → count++ → count=1，返回 1
counter()            → count++ → count=2，返回 2
                       ↑ 同一个闭包 A，同一个 count，状态保留

newCounter := outer() → 又调了一次 outer()，创建全新的 count=0，返回闭包 B
newCounter()         → count++ → count=1，返回 1
                       ↑ 闭包 B 捕获的是自己的 count，和 A 无关
```

### 1.3 核心要点

| 概念 | 说明 |
|------|------|
| **捕获** | 内部函数引用了外部函数的局部变量 |
| **状态保持** | 闭包不销毁 → 被捕获的变量也不销毁 |
| **独立性** | 每次调用 `outer()` 都创建全新的 `count`，互不干扰 |
| **生命周期** | 被捕获变量的生命周期 = 闭包对象的生命周期 |

### 1.4 一句话总结

> 闭包 = 函数 + 它「偷走」的外部变量。函数执行完了，变量还活着。

这个模式在 Go 里常见用途：计数器、迭代器、中间件（HTTP handler）、延迟初始化等。本质上就是用函数封装可变状态，比直接暴露一个全局变量更干净。

## 2. 循环里的常见坑：共享同一个变量

核心就一句话：**闭包捕获的是变量本身，不是当时那一刻的值。**

### 2.1 错误示例：所有闭包共享同一变量 `i`

```go
func wrongClosures() []func() {
    var funcs []func()
    for i := 0; i < 3; i++ {
        funcs = append(funcs, func() {
            fmt.Println(i) // 所有函数都输出 3
        })
    }
    return funcs
}
```

循环里创建了 3 个函数，但它们都引用**同一个**循环变量 `i`。

时间线：

```
i=0 → 创建闭包 A，A 记住的是「变量 i」
i=1 → 创建闭包 B，B 也记住「变量 i」
i=2 → 创建闭包 C，C 还是「变量 i」
循环结束 → i 变成 3（循环条件失败时）
再调用 A/B/C → 全打印 3
```

不是「创建时打印」，而是「**调用时**去读 `i`」。调用时循环早结束了，`i` 已经是 `3`。

可以把它想成：3 个人都拿着同一间仓库的钥匙，仓库里的数字最后变成了 `3`，谁进去看都是 `3`。

### 2.2 正确示例：通过参数传递捕获当前值

```go
func correctClosures() []func() {
    var funcs []func()
    for i := 0; i < 3; i++ {
        funcs = append(funcs, func(num int) func() {
            return func() {
                fmt.Println(num) // 分别输出 0,1,2
            }
        }(i))
    }
    return funcs
}
```

拆开看：

1. `func(num int) func() { ... }` —— 外层函数，参数叫 `num`。
2. `(i)` —— **立刻调用**，把当前的 `i` 传进去。
3. 返回的内层 `func()` 捕获的是 **`num`，不是 `i`**。

每次循环：

| 循环 | 传入 | 内层闭包记住的 |
|------|------|----------------|
| i=0 | num=0 | 自己的 num=0 |
| i=1 | num=1 | 自己的 num=1 |
| i=2 | num=2 | 自己的 num=2 |

`num` 是每次调用外层函数时的**新局部变量**，值已经拷贝好了；之后 `i` 怎么变，都不影响这些 `num`。

### 2.3 和计数器 `count` 的对比

| | `outer` 里的 `count` | 循环里的 `i`（错误写法） |
|--|--|--|
| 想要的效果 | 多个调用共享同一个状态 | 每个闭包各自记住当时的值 |
| 实际捕获 | 一个变量，共享 → 正确 | 一个变量，共享 → 踩坑 |
| 修复思路 | 不需要拆 | 每次复制一份（参数 / 新变量） |

同一机制：闭包绑的是**变量引用**。共享时有时是特性（计数器），有时是 bug（循环里创建多个回调）。

### 2.4 更常见的正确写法

Go 1.22 之前常用：

```go
for i := 0; i < 3; i++ {
    i := i  // 新局部变量，遮蔽循环变量
    funcs = append(funcs, func() {
        fmt.Println(i)
    })
}
```

或上一节那种 IIFE（立即执行函数）传参，本质一样：**制造一个新变量，把当前值拷进去。**

Go 1.22+：`for` 循环每次迭代会创建新的 `i`，错误例子那种坑在很多场景下已经不复现了；面试 / 老代码里仍要会认。

### 2.5 一句话总结

> 错误写法是 3 个函数共用一把钥匙；正确写法是每次循环先复印一张纸条（`num` / `i := i`），再让闭包记住那张纸条。
