# Go 如何进行错误处理

> **Go 错误处理核心：用 `error` 接口显式传递错误、通过 `nil` 判断状态、支持自定义错误类型和 `%w` 错误包装；配合 `panic/recover` 处理致命异常但避免滥用**。

---

## 一、error 接口：显式传递错误

Go 的错误处理核心是用 **`error` 接口**显式传递错误，通过 **nil 判断**操作状态：

```go
type error interface {
    Error() string // 返回错误描述
}
```

```go
f, err := os.Open("file.txt")
if err != nil {
    return err // 显式向上传递
}
```

Go 没有 try/catch，错误是**普通返回值**，需要显式检查——这是 Go 风格（"错误就是值"）。

---

## 二、自定义错误类型

可以自定义错误类型，携带更多上下文：

```go
type MyError struct {
    Code int
    Msg  string
}

func (e *MyError) Error() string {
    return fmt.Sprintf("code=%d: %s", e.Code, e.Msg)
}

func doSomething() error {
    return &MyError{Code: 404, Msg: "not found"}
}

// 用 errors.As 取出自定义错误
var myErr *MyError
if errors.As(err, &myErr) {
    fmt.Println("错误码:", myErr.Code)
}
```

---

## 三、错误包装（%w）

通过 `fmt.Errorf` 的 **`%w`** 包装错误，保留错误链：

```go
func loadConfig() error {
    f, err := os.Open("config.json")
    if err != nil {
        return fmt.Errorf("打开配置失败: %w", err) // 包装
    }
    defer f.Close()
    return nil
}

// 外层用 errors.Is / errors.As 解开
if errors.Is(err, os.ErrNotExist) {
    // 判断根因
}
```

- **`%w`**：包装并保留原错误（可被 `errors.Is/As` 解开）；
- **`errors.Is`**：判断错误链中是否有指定错误；
- **`errors.As`**：把错误链中某个类型的错误取出来。

---

## 四、panic / recover：致命异常

- **panic**：程序出现不可恢复的错误时主动抛出（如数组越界）；
- **recover**：只能在 **defer** 中调用，捕获 panic，让程序恢复。

```go
func safeCall() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("捕获 panic:", r)
        }
    }()
    panic("something went wrong") // 被 recover 捕获
}
```

**注意**：panic/recover **避免滥用**——普通业务错误用 error 返回，只有"程序无法继续"的异常才用 panic。

---

## 五、总结

| 手段 | 用途 |
|------|------|
| `error` 返回值 + nil 判断 | **常规错误处理（主）** |
| 自定义 error 类型 | 携带结构化错误信息 |
| `fmt.Errorf` + `%w` | **错误包装，保留错误链** |
| `errors.Is` / `errors.As` | 判断/提取错误链中的错误 |
| `panic` / `recover` | **致命异常**（避免滥用） |

## 六、高频自测

1. Go 怎么传递错误？
   → **error 接口作为返回值，显式 nil 判断**。
2. `%w` 的作用？
   → **包装错误并保留错误链**，配合 `errors.Is/As` 使用。
3. recover 必须在哪调用？
   → **defer 中**。
4. 什么情况用 panic 而不是 error？
   → **程序无法继续的致命异常**，业务错误一律用 error。

---

## 七、一句话总结

> **Go 错误处理 = error 返回值（显式判断）＋ `%w` 包装 + `errors.Is/As` 解包 ＋ 自定义错误类型**；panic/recover 只留给致命异常。核心原则：**错误是值，别吞掉，带上下文往上抛**。
