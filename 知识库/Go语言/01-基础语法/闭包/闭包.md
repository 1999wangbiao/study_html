# 闭包（Closure）

> **闭包 = 函数 + 它创建时所处的环境（捕获的外部变量）**。即使外层函数已返回、原始作用域已结束，闭包依然能读写这些变量。

---

## 一、什么是闭包

```go
func adder() func(int) int {
    sum := 0                 // sum 是 adder 的局部变量
    return func(x int) int { // 匿名函数引用 sum
        sum += x
        return sum
    }
}

a := adder()
fmt.Println(a(1)) // 1
fmt.Println(a(2)) // 3   ← sum 状态被保留
```

`adder` 返回后 `sum` 并未销毁，而是被闭包捕获，生命周期跟闭包走。Go 中函数是一等公民（可赋值、传参、返回），为闭包提供了基础。

## 二、捕获机制：引用捕获，而非值快照（核心！）

闭包捕获的是**变量的引用（地址）**，不是定义时的值。读写都是同一个变量。

```go
x := 10
f := func() { fmt.Println(x) } // 读的是 x 的当前值
x = 99
f() // 99，不是 10

g := func() { x = 100 }        // 闭包也能修改外部变量
g()
fmt.Println(x) // 100
```

## 三、逃逸分析

被闭包捕获的变量**逃逸到堆上**，由 GC 管理生命周期，无需手动 `new/free`，编译器自动完成。

> 代价：相对纯栈变量，闭包调用有堆分配和间接访问开销。极致性能热路径可改用结构体显式传状态。

## 四、常见用法

### 4.1 计数器 / 状态封装（数据隔离）

```go
func makeCounter() func() int {
    count := 0
    return func() int { count++; return count }
}

c1 := makeCounter()
c2 := makeCounter()
fmt.Println(c1()) // 1
fmt.Println(c1()) // 2
fmt.Println(c2()) // 1   ← c2 是独立状态
```

### 4.2 函数工厂

```go
func greet(prefix string) func(string) string {
    return func(name string) string { return prefix + name }
}
hi := greet("你好，")
fmt.Println(hi("张三")) // 你好，张三
```

### 4.3 回调 / 标准库

```go
sort.Slice(users, func(i, j int) bool { return users[i].Age > users[j].Age })
http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) { ... })
```

### 4.4 goroutine 入口 + 延迟清理（defer）

```go
go func() { /* 后台任务 */ }()

f, _ := os.Open(path)
defer func() { f.Close() }()
```

## 五、易错点

### 5.1 闭包捕获的是引用，不是快照

闭包读到的永远是变量的**当前/最终值**。

```go
x := 5
f := func() { fmt.Println(x) }
x = 100
f() // 100
```

### 5.2 `defer` 立即求值 vs 闭包延迟求值

```go
i := 0
defer fmt.Println(i)          // 普通调用，参数立即求值 → 输出 0
defer func() { fmt.Println(i) }() // 闭包，延迟到 return 时执行 → 输出 100
i = 100
```

### 5.3 循环变量捕获（Go 的著名坑）

```go
for i := 0; i < 3; i++ {
    go func() { fmt.Println(i) }()
}
```

- **Go 1.22 前**：所有闭包共享同一个 `i`，通常输出三个 `3`。
- **Go 1.22 后**：每次迭代 `i` 是新变量，输出 `0 1 2`。

跨版本兼容仍建议显式处理：

```go
// 方式一：传参（推荐）
for i := 0; i < 3; i++ {
    go func(n int) { fmt.Println(n) }(i)
}
// 方式二：局部副本
for i := 0; i < 3; i++ {
    i := i
    go func() { fmt.Println(i) }()
}
```

### 5.4 多个闭包共享同一变量

```go
var funcs []func()
x := 0
for i := 0; i < 3; i++ {
    funcs = append(funcs, func() { x += i }) // 全部捕获同一个 x
}
for _, f := range funcs { f() }
fmt.Println(x) // 所有闭包叠加修改同一个 x
```

### 5.5 误以为"同一个闭包复制后状态独立"

只有**每次调用工厂函数**才生成独立状态；同一个闭包复制给多个变量，状态仍共享。

## 六、迷惑点辨析

### 6.1 闭包 vs 普通函数 vs 方法

| 维度 | 普通函数 | 闭包 | 方法 |
|------|---------|------|------|
| 状态来源 | 无 | 捕获的外部变量 | 接收者 |
| 能否捕获外部变量 | 否 | **能** | 绑定接收者 |
| 典型用法 | 通用逻辑 | 计数器/工厂/回调 | 面向对象封装 |

### 6.2 闭包 vs 结构体 + 方法

| 维度 | 闭包 | 结构体 + 方法 |
|------|------|--------------|
| 状态封装 | 隐式，藏在环境里 | 显式，字段可见 |
| 接口实现 | 无法直接实现接口 | 可实现接口 |
| 调试性 | 状态隐藏，稍难排查 | 字段清晰，易测试 |
| 适用 | 轻量、一次性、函数式组合 | 复杂状态、复用类型、接口化 |

> 经验：简单状态用闭包简洁；状态多、需复用类型或实现接口时用结构体。

### 6.3 闭包捕获的是"值"还是"引用"？

**引用（变量地址）**，不是值，也不是类型。变量逃逸到堆，由 GC 管理生命周期。

## 七、闭包高频自测

1. `defer fmt.Println(i)` 和 `defer func(){fmt.Println(i)}()` 输出一样吗？
   → **不一样**。前者立即求值，后者闭包延迟。
2. 循环里 `go func(){fmt.Println(i)}()` 打印什么？
   → **1.22 前是终值，1.22 后才是各次值**，跨版本建议显式传参。
3. 闭包捕获的是"值"还是"引用"？
   → **引用（变量地址）**。

---

## 八、一句话总结

> **闭包 = 函数 + 它「偷走」的外部变量（捕获的是引用，不是快照）。** 它让函数可以携带状态，是计数器、工厂、回调、中间件的核心机制；它的坑（引用捕获、循环变量、defer 求值时机）是 Go 面试与实战的高频考点。
