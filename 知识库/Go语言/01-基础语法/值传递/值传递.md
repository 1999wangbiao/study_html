# Go 是引用传递还是值传递？

> **Go 只有值传递，没有引用传递。** 但"引用类型"（slice、map、chan、指针）传的是**引用的副本**——副本指向同一份底层数据，所以改内容会影响原变量，改引用本身（重新赋值）不影响。

---

## 一、核心结论

**Go 中所有参数传递都是值传递（pass by value）**，不存在传统意义上的"引用传递"。这意味着函数接收的是参数的**"副本"**，而非参数本身。

但要注意：副本复制的是什么？—— 对"引用类型"来说，复制的是 **（底层指针、容量、长度）** 这个结构体的副本，**本质上还是指向原数据**。

---

## 二、按类型分析

### 1. 基本类型（int、string、bool 等）：典型的值传递

基本类型作为参数传递时，函数会复制参数的值。**修改副本不会影响原变量**。

```go
func f(x int) { x = 100 }

a := 1
f(a)
fmt.Println(a) // 1，不受影响
```

### 2. 复合类型（数组、结构体等）：值传递但成本较高

数组、结构体等复合类型作为参数时，会**复制整个数据结构**（而非引用）。修改副本不会影响原变量，但**复制成本随数据量增大而增加**。

```go
func f(a [3]int) { a[0] = 100 }

arr := [3]int{1, 2, 3}
f(arr)
fmt.Println(arr) // [1 2 3]，拷贝的是整个数组
```

### 3. 引用类型（切片、map、chan、指针等）：值传递"引用的副本"

切片、map、通道等类型本质是"引用类型"，但传递时**仍是值传递**——传递的是"引用的副本"（如切片的指针、长度、容量）。

这些副本**指向底层数据结构**，因此：

- **修改副本指向的底层数据** → 会影响原变量；
- **修改副本本身**（如重新赋值） → 不会影响原变量。

```go
func f(s []int) { s[0] = 100 } // 改底层数据 → 影响原 slice

a := []int{1, 2, 3}
f(a)
fmt.Println(a) // [100 2 3]
```

---

## 三、对比总结

| 类型 | 传递方式 | 修改内容会影响原变量？ | 成本 |
|------|----------|------------------------|------|
| 基本类型 | 值副本 | 否 | 小 |
| 数组/结构体 | **整个数据副本** | 否 | **随体积增大** |
| 切片 | **结构体副本（ptr/len/cap）** | 改元素**是**、改结构**否** | 小 |
| map/chan/指针 | 引用副本 | 是（共享底层） | 小 |

---

## 四、高频自测

1. Go 有引用传递吗？
   → **没有，全部是值传递**。
2. 为什么 slice 传参能改到原数组元素？
   → **传的是 slice 结构体副本，但副本里的指针仍指向原底层数组**。
3. 为什么 append 扩容后原 slice 不受影响？
   → **副本的指针指向了新数组**，与原 slice 分离。

---

## 五、一句话总结

> **Go 只有值传递：基本类型和结构体复制"值"本身（结构体成本高），引用类型复制"引用的副本"（ptr/len/cap）**——副本与原数据共享底层，所以"改内容影响原变量、改引用不影响"。这引出了 slice 传参的两面性。
