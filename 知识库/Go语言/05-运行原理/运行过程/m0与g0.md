# Go 语言 m0 与 g0

> **m0 是程序启动时创建的第一个系统线程（"根线程"），g0 是每个 M 绑定的专属"系统协程"（调度协程）**。两者是理解 Go 运行时初始化和 GPM 调度的基础。

---

## 一、m0 是什么

在 Go 运行时的 runtime 源码中，**m0 是一个特殊的 m 结构体实例**，代表程序启动时创建的第一个系统线程（OS thread），是 Go 调度器初始化和运行的基础。

在 Go 的调度模型中，**m 代表一个操作系统线程**，负责执行 goroutine；m0 是程序启动时由内核创建的初始线程，是整个 Go 程序运行的"根线程"。

### m0 的作用

1. **启动程序初始化**：程序启动时，内核首先创建 m0 线程，执行 Go 运行时的初始化逻辑：
   - 初始化调度器（sched 结构体）、内存分配器、垃圾回收（GC）系统等核心组件；
   - 创建第一个 goroutine（**g0**，特殊的"系统 goroutine"），用于调度其他用户 goroutine。
2. **作为初始执行载体**：m0 是第一个执行 Go 代码的线程，初始化完成后负责执行程序的 main 函数（包装在 main goroutine 中）。
3. **支撑调度器运行**：m0 与其他 m 线程一样参与 goroutine 调度，在特殊场景（程序退出、紧急信号处理）中承担特殊角色。

### m0 的特殊之处

- m0 是**唯一不需要通过 clone 系统调用创建**的 m 实例，由操作系统直接初始化；
- 它的**栈空间是固定的**（通常在进程的栈空间中），不参与 Go 运行时的动态栈管理；
- 在程序生命周期内**始终存在，不会被销毁**。

---

## 二、g0 是什么、有什么用

**g0 是一种特殊的 goroutine（协程）**，被称为"系统栈协程"或"调度协程"，是每个操作系统线程（m）绑定的专属协程，负责协助调度器管理用户协程。

### g0 的核心特性

1. **与线程绑定**：每个 m 都会绑定一个专属的 g0，二者一一对应。程序启动时，第一个 m（m0）先创建第一个 g0，后续新创建的 m 也会自动初始化自己的 g0。
2. **特殊的栈空间**：g0 的栈是**固定大小的系统栈**（而非普通 goroutine 的动态增长栈），通常由操作系统分配（如 Linux 上默认 8MB），用于执行内核相关操作（系统调用、上下文切换）。
3. **无用户代码**：g0 不执行用户编写的业务逻辑，仅运行 Go 运行时的调度代码（协程切换、栈管理、垃圾回收等底层操作）。

### g0 的核心作用

1. **调度用户协程**：需要切换 goroutine 时（如超时、I/O 阻塞），由 g0 执行调度逻辑：保存当前 goroutine 的上下文（寄存器、栈指针等），从调度队列取出下一个待运行的 goroutine，恢复其上下文使其运行。
2. **处理系统调用**：普通 goroutine 执行系统调用（如 `syscall.Read`）时，会切换到 g0 的栈执行内核操作，**避免用户栈被内核污染**。系统调用完成后，再由 g0 切换回原 goroutine。
3. **支持垃圾回收（GC）**：GC 过程中，g0 负责协助**暂停所有用户 goroutine（stop the world）**，执行内存标记/清理操作，完成后再恢复用户 goroutine 运行。
4. **初始化与退出**：程序启动时 g0 负责初始化运行时环境（内存分配器、调度器），并启动 main 函数所在的用户 goroutine；程序退出时 g0 负责清理资源。

## 三、高频自测

1. m0 和普通 m 的区别？
   → **m0 由内核直接创建（无需 clone），栈固定、始终存在**，是运行时的"起点"。
2. g0 与普通 goroutine 的区别？
   → **g0 是每个 M 的系统栈协程，固定栈、不跑用户代码，只做调度/系统调用/GC**。
3. 为什么系统调用要切到 g0 的栈？
   → **避免内核操作污染用户栈**。

---

## 四、一句话总结

> **m0 = 启动时的"根线程"（内核直接创建），g0 = 每个 M 的"调度协程"（系统栈、只干底层活）**。m0 创建第一个 g0 并初始化整个运行时，是 Go 并发从操作系统过渡到用户态调度的关键载体。
