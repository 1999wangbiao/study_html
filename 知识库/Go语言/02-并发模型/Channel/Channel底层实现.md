# Channel 底层实现

> **channel 底层是"带锁的环形队列 + 等待队列"**：缓冲通道用环形队列暂存数据，无缓冲通道直接在 Goroutine 间传递数据；`recvq`/`sendq` 等待队列存储阻塞的 Goroutine，通过唤醒机制协作。所有操作由一把 `lock` 保证并发安全。

---

## 一、核心数据结构：hchan

```go
type hchan struct {
    qcount   uint           // 队列中当前元素数量
    dataqsiz uint           // 环形队列的容量（缓冲大小）
    buf      unsafe.Pointer // 指向环形队列的指针（存储缓冲数据）
    elemsize uint16         // 每个元素的大小（字节）
    closed   uint32         // 通道是否关闭（0：未关闭，1：已关闭）
    elemtype *_type         // 元素类型信息（用于内存操作）
    sendx    uint           // 发送操作的索引（环形队列的写入位置）
    recvx    uint           // 接收操作的索引（环形队列的读取位置）
    recvq    waitq          // 等待接收的 Goroutine 队列
    sendq    waitq          // 等待发送的 Goroutine 队列

    lock mutex              // 保护 hchan 所有字段的互斥锁
}

// 等待队列（双向链表），存储等待的 Goroutine
type waitq struct {
    first *sudog
    last  *sudog
}
```

**channel 的底层实现是带锁的环形队列 + 等待队列：**

- **缓冲通道**：通过环形队列暂存数据，减少阻塞；
- **无缓冲通道**：直接在 Goroutine 间传递数据，实现强同步；
- **等待队列**（recvq/sendq）：存储阻塞的 Goroutine，通过唤醒机制实现协作；
- **互斥锁**：hchan 的所有操作都加锁，保证并发安全。

---

## 二、发送操作（`ch <- val`）

发送操作的核心逻辑是"**将数据放入缓冲，或直接传递给等待的接收方**"：

1. **加锁**：获取 `hchan.lock`，确保操作原子性；
2. **检查通道状态**：若通道已关闭（closed=1），触发 **panic**（向关闭的通道发送数据）；
3. **尝试直接发送给接收方**：若 `recvq`（等待接收的 Goroutine 队列）不为空，**直接将数据拷贝到接收方的内存（跳过缓冲）**，并唤醒接收 Goroutine；
4. **尝试放入缓冲队列**：若缓冲未满（`qcount < dataqsiz`），将数据拷贝到 `buf[sendx]`，更新 `qcount` 和 `sendx`（环形队列索引 +1 取模）；
5. **阻塞等待**：若缓冲已满，当前 Goroutine 包装成 **sudog 加入 sendq**，释放锁并休眠（等待被唤醒）；
6. **解锁**：操作完成后释放锁。

---

## 三、接收操作（`val <- ch` 或 `<-ch`）

接收操作的核心逻辑是"**从缓冲取数据，或等待发送方的数据**"：

1. **加锁**：获取 `hchan.lock`；
2. **检查通道状态**：若通道已关闭且缓冲为空（closed=1 && qcount=0），**返回元素零值**（不阻塞）；
3. **尝试直接从发送方接收**：若 `sendq`（等待发送的 Goroutine 队列）不为空：
   - 若为**无缓冲通道**，直接从发送方拷贝数据到接收变量；
   - 若为**缓冲通道且缓冲已满**，先从缓冲取一个元素到接收变量，再将发送方的数据放入缓冲；
   - 唤醒发送 Goroutine；
4. **尝试从缓冲队列取数据**：若缓冲非空（qcount > 0），从 `buf[recvx]` 拷贝数据到接收变量，更新 `qcount` 和 `recvx`。

---

## 四、关闭操作（`close(ch)`）

关闭操作的核心是"**标记通道为关闭状态，唤醒所有等待的 Goroutine**"：

1. **加锁**：获取 `hchan.lock`；
2. **检查通道状态**：若通道已关闭（closed=1），触发 **panic**（重复关闭）；
3. **标记为关闭**：设置 `closed=1`；
4. **唤醒等待队列**：
   - 唤醒 `recvq` 中所有等待的接收 Goroutine（**返回零值**）；
   - 唤醒 `sendq` 中所有等待的发送 Goroutine（**触发 panic**，因向关闭的通道发送数据）；
5. **清空缓冲**：（逻辑上）标记缓冲数据可被读取（直到为空）；
6. **解锁**：释放锁。

---

## 五、关键结论

| 操作 | 行为 |
|------|------|
| 向已关闭 channel 发送 | **panic** |
| 从已关闭且为空的 channel 接收 | **返回零值**（不阻塞） |
| 重复 close | **panic** |
| 无缓冲 channel | 收发直接传递 + 强同步 |
| 缓冲 channel | 环形队列暂存 |

## 六、高频自测

1. channel 底层由什么组成？
   → **带锁的环形队列（buf）+ 等待队列（recvq/sendq）**。
2. 向关闭的 channel 发送会怎样？
   → **panic**。
3. 从关闭的空 channel 接收会怎样？
   → **返回零值**，不阻塞。
4. 无缓冲和缓冲 channel 的本质区别？
   → **无缓冲直接传（强同步）；缓冲走环形队列（减阻塞）**。

---

## 七、一句话总结

> **channel = 环形队列 + 等待队列 + 一把锁**：收发先加锁，能直接交接就交接（跳过缓冲），不行就进环形队列，满了就挂到 recvq/sendq 等待唤醒。关闭时唤醒所有等待者——向关闭的发 panic、从关闭的空通道收零值。
