# Go 中的 CSP 模型

> **CSP（Communicating Sequential Processes，通信顺序进程）＝ 通过"通信"而非"共享内存"来协作**。Go 的 motto 是："不要通过共享内存来通信，而要通过通信来共享内存。"

---

## 一、CSP 是什么

通过**通信**而非共享内存实现进程间协作，强调"**顺序进程**"与"**消息传递**"的结合。

核心思想：

- 每个 Goroutine 是独立执行的"顺序进程"；
- 进程之间**不共享变量**，而是通过**通道（channel）**传递消息；
- Go 通过 `go` 关键字 + channel 把 CSP 落到语言层面。

---

## 二、CSP 的三个优势

### 1. 避免竞态条件

数据通过**通道传递**，而非多个 Goroutine 直接修改共享内存，从根本上减少了锁的使用，降低了并发错误的概率。

### 2. 清晰的协作关系

通道明确了 Goroutine 之间的**依赖关系**（谁生产数据，谁消费数据），代码逻辑更易理解和维护。

### 3. 天然的同步机制

通道的**发送/接收操作是阻塞**的，无需额外的同步工具（如 Mutex）即可实现 Goroutine 之间的协调。

---

## 三、与"共享内存 + 锁"的对比

| 维度 | 共享内存 + 锁 | CSP（channel 通信） |
|------|---------------|---------------------|
| 协作方式 | 多个 goroutine 改同一块内存 | **通过 channel 传消息** |
| 同步手段 | Mutex / RWMutex | **channel 天然阻塞** |
| 出错风险 | 竞态条件多，难排查 | 低 |
| 谁生产谁消费 | 不明确 | **代码可读，明确** |
| Go 推荐度 | 特定场景可用 | **语言级推荐** |

> 经典代码示例：

```go
// 共享内存 + 锁（不推荐）
var count int
var mu sync.Mutex
go func() { mu.Lock(); count++; mu.Unlock() }()

// CSP：通过 channel 传递
ch := make(chan int)
go func() { ch <- 1 }()  // 发送
n := <-ch                // 接收（阻塞直到有数据）
```

## 四、高频自测

1. CSP 的核心主张是什么？
   → **不要通过共享内存来通信，要通过通信来共享内存**。
2. CSP 如何避免竞态？
   → **数据通过 channel 传递，不直接共享内存，减少锁使用**。
3. channel 的阻塞特性带来了什么？
   → **天然的同步机制**，收发无需额外加锁。

---

## 五、一句话总结

> **CSP = 用 channel 通信而不是共享内存**。它让并发协作从"争抢共享数据"变成"清晰的数据流"，天然同步、低竞态，是 Go 并发哲学的基石。
