# Go 中 Goroutine 常见的通信方式

> **Go 推荐 channel（通信共享内存）；也可用共享内存 + 锁；辅助手段：Context 控制生命周期、WaitGroup 协调完成**。

---

## 一、通道（channel）：Go 推荐的通信方式

channel 是 Goroutine 间**最常用、最安全**的通信方式，通过传递数据实现协作，底层由同步机制保证线程安全：

```go
ch := make(chan int)
go func() { ch <- 42 }() // 生产者发送
v := <-ch                // 消费者接收
```

- 符合 CSP 思想：**通过通信共享内存**；
- 收发天然阻塞，自带同步；
- 支持缓冲/无缓冲、可配合 select 做多路监听。

---

## 二、共享内存 + 锁：通过共享变量通信

多个 Goroutine 共享同一块内存区域（如全局变量），通过**锁（sync.Mutex 或 sync.RWMutex）**保证并发安全：

```go
var count int
var mu sync.Mutex

go func() {
    mu.Lock()
    count++
    mu.Unlock()
}()
```

- 需**手动控制同步**，容易引发竞态条件；
- Go 通常不推荐，但在特定场景（如高频读写同一结构体）适用。

---

## 三、Context：控制 Goroutine 生命周期

`context.Context` 主要用于**传递取消信号、超时信号**，协调多个 Goroutine 同步退出，是"**控制流通信**"的核心方式：

```go
ctx, cancel := context.WithCancel(context.Background())
go worker(ctx) // 内部监听 <-ctx.Done()

cancel() // 通知 worker 退出
```

---

## 四、WaitGroup：等待多个 Goroutine 完成

`sync.WaitGroup` 用于**等待一组 Goroutine 全部执行完毕**，本质是通过计数器实现的同步机制，不直接传递数据，而是协调执行顺序：

```go
var wg sync.WaitGroup
wg.Add(3)

for i := 0; i < 3; i++ {
    go func() {
        defer wg.Done()
        // 干活
    }()
}

wg.Wait() // 等 3 个都完成
```

---

## 五、总结对比

| 方式 | 用途 | 是否传数据 |
|------|------|-----------|
| **channel** | 数据传递（推荐） | 是 |
| 锁 + 共享内存 | 保护共享变量 | 否（共享） |
| **Context** | 取消/超时信号 | 否（控制流） |
| **WaitGroup** | 等待完成 | 否（协调） |

---

## 六、一句话总结

> **channel 传数据（首选）、锁护共享（备选）、Context 管退出、WaitGroup 等完成**。Go 的哲学是"能用 channel 就不用锁"，控制流用 Context、汇合用 WaitGroup。
