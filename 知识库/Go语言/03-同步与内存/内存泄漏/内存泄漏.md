# Go 常见内存泄漏原因

> **Go 常见内存泄漏：goroutine 没正常退出（最常见）、资源没关闭、切片大数组被小切片引用、闭包内部变量被外部使用**。核心是"对象仍然被引用，GC 无法回收"。

---

## 一、未关闭的资源

程序打开的资源（文件、网络连接、数据库连接等）若未正确关闭，会导致资源关联的内存无法释放，造成泄漏。

```go
f, _ := os.Open(path)
// 忘记 f.Close() → 文件句柄泄漏
```

---

## 二、goroutine 泄漏（最常见）

Goroutine 若因逻辑错误一直处于**阻塞状态（未退出）**，其占用的栈内存、引用的对象都不会被回收，导致泄漏。这是 Go 中最容易出现的内存泄漏场景。

### 无缓冲 channel 的发送/接收未配对

若一个 Goroutine 向无缓冲 channel 发送数据，但**没有对应的接收者**（或反之），Goroutine 会**永久阻塞**。

```go
ch := make(chan int)
ch <- 1 // 没人接收 → 永久阻塞 → 泄漏
```

### Goroutine 内部死循环

若 Goroutine 陷入无限循环且**没有退出条件**，会一直占用内存。

### 未处理的 context.Done()

使用 context 控制 Goroutine 生命周期时，若**未监听 context.Done()**，Goroutine 可能在上下文取消后仍继续运行。

```go
// 错误：只等待任务完成，不监听 ctx.Done()
go func() {
    for {
        select {
        case task := <-ch:
            handle(task)
        // case <-ctx.Done(): return  ← 缺失导致泄漏
        }
    }
}()
```

## 三、切片导致的内存泄漏

切片的底层数组若被引用，**即使切片本身缩小，底层数组也不会被回收**，可能导致大量未使用内存被占用。

**解决**：复制切片内容到新数组，切断对原数组的引用：

```go
func leak() []int {
    large := make([]int, 10000) // 大数组
    return large[:10]           // 返回切片（仅引用大数组的前 10 个元素）
}

func fixLeak() []int {
    large := make([]int, 10000)
    small := make([]int, 10)
    copy(small, large[:10]) // 复制到新切片
    return small            // 大数组可被 GC 回收
}
```

## 四、闭包内部变量被外部使用

闭包捕获的外部变量会**逃逸到堆上**，若闭包被长期持有（如全局缓存），其捕获的变量也会长期存活，间接造成内存占用。

```go
var handlers []func()
for i := 0; i < 1000; i++ {
    bigData := make([]byte, 1024*1024) // 大对象
    handlers = append(handlers, func() { _ = bigData }) // 闭包捕获 bigData → 全部逃逸到堆
}
// 所有 bigData 都被 handlers 引用，无法回收
```

## 五、如何排查

1. **pprof**：`go tool pprof` 分析 heap / goroutine profile，定位堆积的 goroutine 和大内存对象；
2. **`runtime.NumGoroutine()`**：观察 goroutine 数量是否持续增长；
3. **`go vet`**：静态检查部分资源未关闭问题。

---

## 六、高频自测

1. Go 最常见的内存泄漏是什么？
   → **goroutine 泄漏（阻塞未退出）**。
2. 无缓冲 channel 收发不配对会怎样？
   → **发送方/接收方永久阻塞**，形成 goroutine 泄漏。
3. 大切片返回前 10 个元素为什么会泄漏？
   → **返回的子切片仍引用整个大底层数组**；用 `copy` 到新切片可解决。
4. 如何避免 goroutine 泄漏？
   → **监听 `ctx.Done()` / 使用 select + 超时 / 确保 channel 有配对**。

---

## 七、一句话总结

> **内存泄漏 = 对象仍被引用、GC 收不掉**。高发场景：goroutine 阻塞不退出（channel 不配对、死循环、忽略 ctx.Done）、资源不 close、小切片拖着大数组、闭包拖着逃逸变量——用 pprof 和 goroutine 数量监控定位。
