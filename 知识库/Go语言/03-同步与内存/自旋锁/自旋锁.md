# 什么是自旋锁？

> **自旋锁 = 获取不到锁时"忙等"（循环重试），而不是阻塞休眠**。适合锁持有时间极短的场景（纳秒/微秒级）。Go 的 Mutex 在正常模式下也先自旋数次再睡眠。

---

## 一、自旋锁是什么

**自旋锁（Spin Lock）** 是一种特殊的锁机制，当线程（或 Goroutine）尝试获取锁而未能成功时，**不会立即阻塞休眠**，而是**循环重试（自旋）直到获取到锁为止**。这种"忙等"特性使其适用于锁持有时间极短的场景。

### 与互斥锁（sync.Mutex）的区别

- **互斥锁**获取失败时，线程会进入**阻塞状态**（放弃 CPU，由操作系统调度唤醒）；
- **自旋锁**获取失败时，线程会**持续占用 CPU 并循环检查锁状态**（忙等）。

```text
互斥锁：拿不到 → 睡眠，等唤醒（放弃 CPU，省电但切换有开销）
自旋锁：拿不到 → 循环检查锁，直到拿到（占 CPU，但无切换开销）
```

---

## 二、自旋锁的主要使用场景

自旋锁适用于**锁持有时间极短（纳秒或微秒级）**且并发冲突不频繁的场景，典型包括：

### 1. 内核态编程

操作系统内核中，当临界区操作非常短时（如修改内核数据结构），自旋锁可**避免线程切换的开销**（内核态线程切换成本高）。

### 2. 多处理器系统的短临界区

在多 CPU 环境下，若一个 CPU 上的线程持有锁，另一个 CPU 上的线程**自旋等待可能比阻塞更高效**（无需上下文切换）。

### 3. 高性能并发数据结构

如**无锁队列、计数器**等，操作时间极短，自旋等待的成本低于阻塞唤醒。

### 4. Go 语言 sync.Mutex 内部优化

Go 的互斥锁在正常模式下，会**先自旋几次尝试获取锁，失败后才进入阻塞队列**，平衡性能和公平性。

---

## 三、自旋锁的优缺点

| 维度 | 自旋锁 | 互斥锁 |
|------|--------|--------|
| 获取失败时 | **忙等（占 CPU）** | 阻塞睡眠（让出 CPU） |
| 适合临界区 | **极短**（纳秒/微秒） | 可长可短 |
| 切换开销 | 无 | 有（上下文切换） |
| CPU 消耗 | **高**（忙等） | 低 |
| 风险 | 长期自旋浪费 CPU | 切换频繁开销大 |

---

## 四、高频自测

1. 自旋锁获取失败时干什么？
   → **循环重试（忙等），不睡眠**。
2. 自旋锁适合什么场景？
   → **锁持有时间极短、冲突不频繁**（如内核短临界区）。
3. Go 的 Mutex 用自旋吗？
   → **用**，正常模式下先自旋数次（最多 4 次），失败才进阻塞队列。

---

## 五、一句话总结

> **自旋锁 = 拿不到锁就"忙等"（循环检查）而非睡眠**，省掉切换开销但烧 CPU，只适合**临界区极短**的场景。Go 的 Mutex 策略是"先自旋几次、再睡"，两头的好处都占一点。
