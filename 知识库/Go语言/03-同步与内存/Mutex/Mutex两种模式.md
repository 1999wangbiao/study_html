# Mutex 的两种模式：正常模式与饥饿模式

> **正常模式**：释放锁时唤醒最早的 goroutine，但新来的可以插队竞争（适合低竞争、吞吐优先）；**饥饿模式**：等待超过 1ms 后切换，严格 FIFO 排队获取（防止老 goroutine 饿死）。

---

## 一、正常模式（Normal Mode）

正常模式是 Mutex 的**默认工作模式**，也是大多数情况下的运行模式：

1. **锁竞争机制**：当一个 Goroutine 释放锁时，会唤醒等待队列中**最早的 Goroutine（队首元素）**。但此时，**新到达的 Goroutine 可以和被唤醒的 Goroutine 一起竞争锁**（通过自旋或直接尝试获取）；
2. **潜在问题**：在高竞争场景下，新 Goroutine 可能频繁插队，导致等待队列中的 Goroutine 长期获取不到锁，陷入**"饥饿"状态**（等待时间超过 **1ms** 时，会触发模式切换）。

```text
正常模式：新来的 goroutine 可以"插队"与被唤醒者竞争
释放锁 → 唤醒队首 → 新来的 和 队首 一起抢
```

---

## 二、饥饿模式（Starvation Mode）

当某个 Goroutine 等待锁的时间超过 **1ms** 时，Mutex 会从正常模式切换到饥饿模式：

1. **严格的 FIFO 机制**：锁的所有权**直接传递给等待队列中最早的 Goroutine（队首）**，新到达的 Goroutine **不会参与竞争**，而是直接加入等待队列尾部（**不允许插队**）；
2. **模式切换回正常模式的条件**（满足任一即可）：
   - 持有锁的 Goroutine 是等待队列中的**最后一个元素**（队列已空）；
   - 持有锁的 Goroutine **等待时间小于 1ms**。

满足任一条件时，锁会从饥饿模式**切换回正常模式**，以恢复吞吐量。

---

## 三、模式切换的触发流程

1. **正常模式 → 饥饿模式**：当一个 Goroutine 等待锁的时间**超过 1ms**，且当前处于正常模式时，会将锁标记为饥饿模式，并将自己移到等待队列头部；
2. **饥饿模式 → 正常模式**：当持有锁的 Goroutine 释放锁时，若发现：
   - 等待队列中只有自己（无其他等待者），或
   - 自己的等待时间小于 1ms，
   则将锁切换回正常模式。

```text
正常模式 ←→ 饥饿模式
   │              │
   │ 等锁>1ms      │ 队尾无人 或 等锁<1ms
   └──────────────┘
```

---

## 四、两种模式对比

| 维度 | 正常模式 | 饥饿模式 |
|------|----------|----------|
| 触发条件 | 默认 | 等锁超 1ms |
| 竞争方式 | 新来的可插队 | **严格 FIFO，禁止插队** |
| 吞吐量 | 高 | 较低 |
| 公平性 | 低（可能饥饿） | **高（不饿死）** |
| 回归条件 | — | 队尾无人 或 等锁 <1ms |

---

## 五、高频自测

1. 正常模式允许什么？
   → **新 goroutine 插队竞争**，吞吐高但可能饥饿。
2. 饥饿模式什么时候触发？
   → **等锁超过 1ms**。
3. 饥饿模式如何分配锁？
   → **严格 FIFO，直接传给队首**，新来的只能排队。
4. 什么时候切回正常模式？
   → **持有者成为最后一个等待者，或持有者等待时间 <1ms**。

---

## 六、一句话总结

> **Mutex 双模式：默认正常模式（新来可插队，吞吐优先）→ 等锁超 1ms 切饥饿模式（严格 FIFO，防饿死）→ 队尾无人或等锁 <1ms 切回正常**。用模式切换在"吞吐量"和"公平性"间自适应。
