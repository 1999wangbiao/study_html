# Go GC 触发条件

> **Go 的 GC 自动触发，主要时机：内存分配达到阈值（默认 100%，可动态调整）、长时间未触发强制触发（默认 2 分钟）、手动调用 `runtime.GC()`**。

---

## 一、三种触发条件

### 1. 内存分配达到阈值

当新分配的内存达到**上一次 GC 后存活内存的一定比例**（默认 100%，可动态调整）时触发。

> 通过 `GOGC` 环境变量或 `debug.SetGCPercent()` 调整：`GOGC=100` 表示新分配内存达到存活内存的 100% 时触发 GC。

### 2. 定时触发

若**长时间未触发 GC（默认 2 分钟）**，会强制触发一次，避免内存泄漏累积。

### 3. 手动触发

通过 **`runtime.GC()`** 函数手动触发（一般用于测试或特殊场景）。

```go
runtime.GC() // 手动触发一次 GC
```

---

## 二、相关机制补充

- **GOGC 调优**：`GOGC=off` 可关闭自动 GC（生产不建议）；`GOGC=200` 降低触发频率（用内存换 CPU）；
- **`debug.FreeOSMemory()`**：手动把空闲内存归还给操作系统；
- **`runtime.SetFinalizer`**：对象被回收前执行回调（谨慎使用，不保证执行时机）。

---

## 三、高频自测

1. GC 默认在什么比例触发？
   → **新分配内存达到上次 GC 后存活内存的 100%（GOGC=100）**。
2. 长时间没 GC 会怎样？
   → **默认 2 分钟后强制触发一次**，防止内存泄漏累积。
3. 如何手动触发 GC？
   → **`runtime.GC()`**。

---

## 四、一句话总结

> **GC 触发 = 内存分配超阈值（默认 100%）＋ 超过 2 分钟强制一次 ＋ 手动 `runtime.GC()`**。调 GOGC 可改变触发频率，在"吞吐量"和"内存占用"之间取舍。
