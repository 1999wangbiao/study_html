# Go 原子操作的实现原理与锁的区别

> **原子操作（sync/atomic）= 无锁同步，基于 CPU 原子指令直接操作内存**（CAS、XADD 等），效率极高但功能有限；**锁 = 基于操作系统同步机制，可保护复杂临界区**，功能灵活但有性能开销。

---

## 一、原子操作是什么

**原子操作（`sync/atomic` 包）** 是一种**无锁**的同步机制，通过 CPU 提供的**原子指令**直接操作内存，确保操作的**不可分割性（原子性）**，从而无需通过锁来保护共享资源。

### 常见 CPU 原子指令

- **CAS（Compare-And-Swap）**：比较内存中的值与预期值，若相等则替换为新值（如 `LOCK CMPXCHG` 指令）；
- **原子增减**：如 `LOCK XADD`（原子加法）、`LOCK XDEC`（原子减法）；
- **原子加载/存储**：如 MOV 指令配合内存屏障，确保读写的原子性。

### Go 常用 API

```go
atomic.AddInt64(&n, 1)                    // 原子累加 int64
atomic.CompareAndSwapInt32(&v, old, new)  // CAS：比较并交换
atomic.LoadUint64(&v)                     // 原子读取
atomic.StoreUint64(&v, 100)               // 原子写入
atomic.SwapInt32(&v, 10)                  // 原子交换
```

```go
var count int64

go func() {
    atomic.AddInt64(&count, 1) // 无需锁，原子 +1
}()
```

## 二、原子操作与锁的区别

| 维度 | 原子操作 | 锁（Mutex） |
|------|----------|-------------|
| 实现基础 | **CPU 硬件指令** | **操作系统同步机制** |
| 保护范围 | **单个内存操作** | 复杂临界区（多步操作） |
| 性能 | **极高**（无锁、无上下文切换） | 有开销（自旋/阻塞/唤醒） |
| 功能 | 有限（增减/CAS/读写） | **灵活（任意代码段）** |
| 适用场景 | 简单变量的并发控制 | 多步操作或复杂数据结构 |
| 是否阻塞 | 否 | 可能阻塞 |

---

## 三、怎么选

- **简单计数器 / 标志位 / 单一变量更新** → 用原子操作（`atomic.AddXxx`、`CAS`）；
- **多步操作（先读后写、复合逻辑）或复杂数据结构** → 用锁（Mutex）；
- 原子操作可用来实现**自旋锁、无锁数据结构**（如 CAS 循环）。

---

## 四、高频自测

1. 原子操作基于什么实现？
   → **CPU 硬件原子指令**（CAS、XADD 等）。
2. 原子操作和锁谁更快？
   → **原子操作**（无锁、无切换开销），但只能做简单操作。
3. 什么时候必须用锁？
   → **多步操作 / 复杂临界区**，原子操作无法覆盖时。

---

## 五、一句话总结

> **原子操作 = CPU 指令级无锁同步（快但简单），锁 = OS 级同步（慢但通用）**。单变量的增减/比较交换用 atomic，多步或复杂逻辑用 Mutex。
