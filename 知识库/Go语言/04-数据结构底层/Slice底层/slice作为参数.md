# slice 作为函数参数传递，会改变原 slice 吗？

> **取决于操作类型**：**修改元素 → 会改变原 slice**（共享底层数组）；**修改结构（append 扩容 / 重新赋值）→ 不会改变原 slice**（副本分离）。本质是"传的是 slice 结构体副本，但副本里的指针仍指向原数组"。

---

## 一、核心原理

slice 在 Go 中是**引用类型**，但函数传参仍是**值传递**——传递的是 slice **结构体的副本**：

```go
type slice struct {
    pointer *array // 指向底层数组的指针
    len     int    // 长度
    cap     int    // 容量
}
```

当 slice 作为参数传给函数时，函数接收的是**这个结构体的副本**，但**副本中的指针仍指向原底层数组**。因此：改数据改得到（共享数组），改结构改不到（副本的 len/cap 独立）。

---

## 二、两种情况分析

### 1. 修改 slice 中的元素 → 会改变原 slice

由于副本和原 slice **共享底层数组**，修改元素会直接操作底层数组，原 slice 会受到影响：

```go
func modifyElement(s []int) {
    s[0] = 100 // 修改底层数组元素
}

func main() {
    a := []int{1, 2, 3}
    modifyElement(a)
    fmt.Println(a) // 输出 [100 2 3]，原 slice 被改变
}
```

### 2. 修改 slice 的结构（长度、容量或重新分配底层数组）→ 不会改变原 slice

若函数内对 slice 进行 `append` 导致扩容（底层数组更换），或直接重新赋值，只会影响**函数内的副本**，原 slice 不受影响：

```go
func modifySlice(s []int) {
    s = append(s, 4) // 若触发扩容，副本指向新数组
    s[0] = 100       // 仅修改副本的底层数组（可能是新数组）
}

func main() {
    a := []int{1, 2, 3}
    modifySlice(a)
    fmt.Println(a) // 输出 [1 2 3]，原 slice 未改变
}
```

> 注意：如果 append **没触发扩容**（cap 足够），append 写入的位置仍在原底层数组内，会"间接"影响原数组的对应位置——只是原 slice 的 len 不变，看不到新元素。

---

## 三、如何让函数内修改结构同步到外部？

需通过**指针传递（`*[]int`）**：

```go
func appendAt(s *[]int, v int) {
    *s = append(*s, v) // 直接改调用方的 slice 结构
}

func main() {
    a := []int{1, 2, 3}
    appendAt(&a, 4)
    fmt.Println(a) // [1 2 3 4]
}
```

---

## 四、总结

- **修改元素**：会改变原 slice（共享底层数组）；
- **修改结构**（如 append 扩容、重新赋值）：不会改变原 slice（副本与原 slice 分离）；
- 若需在函数内修改 slice 结构并同步到外部，需通过**指针传递（`*[]int`）**。

---

## 五、高频自测

1. 函数内 `s[0] = 100` 会影响外部吗？
   → **会**（共享底层数组）。
2. 函数内 `append` 扩容会影响外部吗？
   → **不会**（副本指向了新数组）；未扩容时可能影响原数组对应位置。
3. 怎么让 append 结果同步出去？
   → **传 `*[]int` 指针**。

---

## 六、一句话总结

> **slice 传参 = 传结构体副本，但指针共享底层数组**：改元素改得到（共享数组），append 扩容改不到（副本分离）。要改结构就传 `*[]int`。
