# Map 如何实现扩容

> **当负载因子超过 6.5（键值对数量 / 桶数）或溢出桶过多时触发扩容**。两种类型：**翻倍扩容**（桶数 ×2，负载过高）和**等量扩容**（桶数不变，整理溢出桶）。扩容是**渐进式**的，不一次完成。

---

## 一、扩容触发条件

当 map 中的键值对数量过多，或溢出桶链过长时，会触发扩容，避免哈希冲突加剧导致性能下降：

1. **负载因子超过 6.5**：`count / (2^B) > 6.5`，即平均每个桶装超过 6.5 个键值对；
2. **溢出桶过多**：溢出桶数量超过一定阈值（哈希分布不均导致）。

---

## 二、两种扩容类型

### 1. 翻倍扩容（Growing）

- **触发**：键值对数量超过阈值（通常是**桶数量的 6.5 倍**）；
- **做法**：新桶数量变为原来的 **2 倍（B+1）**，所有键值对**重新哈希**到新桶中，降低负载因子。

### 2. 等量扩容（Same-size Grows）

- **触发**：**溢出桶过多但键值对总数不多**（哈希分布不均，很多桶空、很多桶链长）；
- **做法**：**重新分配同样数量的桶**，将键值对重新哈希分散到新桶中，减少溢出桶数量（解决"哈希分布不均"问题）。

---

## 三、扩容过程：渐进式

扩容是**渐进式**的（不一次性完成）：

- 每次操作（增删改查）会**迁移部分键值对**到新桶，避免单次扩容耗时过长影响性能；
- 迁移期间，hmap **同时持有旧桶和新桶**，直到所有键值对迁移完成；
- 迁移进度由 `oldbuckets`（旧桶指针）和 `nevacuate`（已迁移数量）记录。

```text
触发扩容
  ↓
分配新桶（翻倍 or 等量）
  ↓
每次 map 操作顺带迁移一部分键值对
  ↓
全部迁移完成 → 释放旧桶
```

---

## 四、核心字段回顾

| 字段 | 作用 |
|------|------|
| `count` | 键值对数量（负载因子计算用） |
| `B` | 桶数量对数（桶数 = 2^B） |
| `oldbuckets` | 扩容时指向旧桶数组（渐进式迁移期间非 nil） |
| `nevacuate` | 已迁移的旧桶数量 |
| `noverflow` | 溢出桶数量（判断是否需等量扩容） |

---

## 五、高频自测

1. 负载因子超过多少触发扩容？
   → **6.5**。
2. 翻倍扩容和等量扩容分别解决什么问题？
   → **翻倍解决"键值对太多"（降负载）；等量解决"溢出桶太多"（哈希分布不均）**。
3. 扩容是一次性完成吗？
   → **不是，渐进式**，每次增删改查迁移一部分。
4. 扩容期间 map 还能用吗？
   → **能**，新旧桶并存，查询会先看新桶再看旧桶。

---

## 六、一句话总结

> **扩容 = 负载因子超 6.5 翻倍（B+1）或溢出桶过多等量整理**；过程是**渐进式迁移**（oldbuckets 记录旧桶，每次操作搬一点），避免一次性扩容卡顿。
