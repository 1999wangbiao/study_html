### 1. HTTP请求中的GET和POST有什么主要区别？（5分）

**A.** GET请求通常用于请求数据，POST请求只用于提交数据。

**B.** GET请求的数据会附加在URL之后，POST请求的数据放在请求体内。

**C.** GET请求可以获取新的资源，POST请求无法获取资源。

**D.** GET请求不安全，POST请求比GET请求安全。

**正确答案：** B　|　**我的答案：** B　|　✅

**答案详解：** 本题考察 HTTP 请求方法 GET 与 POST 的核心区别。✅ B：GET 的参数以查询字符串形式附加在 URL 之后，POST 的数据则放在请求体（Body）内，这正是二者最本质的区别。❌ A：POST 并非"只用于提交数据"，用 POST 携带查询条件获取数据同样常见，此说法过于绝对。❌ C：GET 和 POST 都能获取资源，"POST 无法获取资源"不成立。❌ D：安全与否取决于 HTTPS、参数可见性、后端校验等实现，POST 并不天然更安全。

**A.** JWT 对用户密码进行了极强的加密，即便被黑客拦截也绝对安全。

**B.** 传统 Session 强依赖于服务端内存或集中存储，JWT 是"无状态"的。

**C.** JWT 生成的字符串非常短，比传统的 SessionID 更省网络带宽。

**D.** JWT 只能在 Go 语言和前端之间解析，跨语言安全性极高。

**正确答案：** B　|　**我的答案：** B　|　✅

**答案详解：** 本题考察 JWT 相比传统 Session 的核心优势——无状态。✅ B：传统 Session 依赖服务端内存或 Redis 等集中存储，水平扩展时需共享存储；JWT 把用户信息与签名编码在令牌自身，服务端无需存储即可验签，天然支持水平扩展。❌ A：JWT 只是 Base64 编码而非强加密，载荷可被读取、仅能防篡改，仍需 HTTPS 保护，谈不上"绝对安全"。❌ C：JWT 由 Header、Payload、Signature 三段组成，通常比 SessionID 长得多，并非更省带宽。❌ D：JWT 是开放标准、各语言都能解析，但"只能在 Go 与前端之间解析"说法错误，也与安全性无关。

### 26. 前后端分离开发时，前端调用后端经常会遇到可怕的 CORS 报错。导致跨域报错的根本原因是什么？它为了解决什么痛点而存在？（5分）
