**答案详解：** 核心是静态局部变量的初始化时机：动态初始化在首次执行到声明处时完成一次，此后值被保留。✅ A 静态局部变量首次进入时完成初始化，后续每次 ++ 会沿用上次的值继续递增，正确。✅ B 初值在首次执行到声明处时就已固化，若 srand(100) 发生在该初始化之后，无法回头改写已经写入的初值，正确。✅ C 去掉 static 后每次进入都可能重新执行初值表达式，失去「单次保留计数」的语义，正确。✅ D return 语句把 int 作为 main 的退出码返回，平台对退出码范围有限制确有其事，但不影响对存储期与初始化顺序的讨论，正确。

>     QSharedPointer<RingA> back;
> };
> void link(const QSharedPointer<RingA>& a, const QSharedPointer<RingB>& b) {
>     a->next = b;
>     b->back = a;
> }
> 
> ```

**A.** `link` 执行后，经成员 `next` 与 `back` 互指形成 `QSharedPointer` 环时，即便用于调用 `link` 的局部 `QSharedPointer` 已离开作用域，堆上的 `RingA` 与 `RingB` 两侧强引用计数仍可能均不归零，析构链无法走通。

**B.** 若将 `RingB::back` 改为 `QWeakPointer<RingA>`，且成员内不把 `lock()` 得到的 `QSharedPointer<RingA>` 再长期存回成环，通常可在无外部强引用时析构 `RingA` 与 `RingB`。

**C.** `QWeakPointer<RingA>` 一般由已有 `QSharedPointer<RingA>` 构造而来，与对应强引用共享同一套引用计数语义。

**D.** 若 `RingA* raw` 恰好指向某块已被 `QSharedPointer<RingA>` 接管的内存，则写 `QWeakPointer<RingA> w(raw)` 后，`w` 就会**自动挂接**到那份强引用内部的计数上。

**正确答案：** ABC　|　**我的答案：** AB　|　❌

**答案详解：** 核心是 QSharedPointer 环与 QWeakPointer 的构造方式：弱引用必须由已有强引用/弱引用构造而来，从裸指针无法得知控制块信息。✅ A link 执行后经 next 与 back 互指形成 QSharedPointer 环，即便用于调用 link 的局部强引用离开作用域，两侧强引用计数仍可能不归零、析构链无法走通，正确。✅ B 将一侧改为 QWeakPointer 且不把 lock() 结果长期存回成环，通常可在无外部强引用时析构两侧，正确。✅ C QWeakPointer 一般由已有 QSharedPointer 构造而来，与对应强引用共享同一套引用计数语义，正确。❌ D 直接用裸指针 raw 构造 QWeakPointer 无法自动挂接已有强引用的控制块（从裸指针得不到控制块信息），w 通常为空，说法错误。作答漏选了 C。
