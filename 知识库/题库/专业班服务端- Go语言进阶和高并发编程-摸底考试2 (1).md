### 1. 下列关于 Go 语言的切片声明，哪个是错误的？（5分）

**A.** var slice1 []int

**B.** slice2 := []int{}

**C.** slice3 := make([]int, 0)

**D.** slice4 := new([]int)

**正确答案：** D　|　**我的答案：** D　|　✅

**答案详解：** 该题考查切片的声明方式。A 正确：var slice1 []int 声明一个 nil 切片；B 正确：slice2 := []int{} 通过字面量创建一个长度和容量都为 0 的空切片（非 nil）；C 正确：slice3 := make([]int, 0) 用 make 创建长度、容量均为 0 的切片，与 B 都能直接 append 使用。D 错误：new([]int) 分配一个零值的切片头并返回其指针（*[]int），得到的仍是一个 nil 切片，而不是可直接使用的切片值，故不是正确的切片声明方式。题目问"哪个是错误的"，故选 D。

**答案详解：** 该题考查通过指针访问结构体成员字段的写法。A 正确：p.name，Go 允许对指向结构体的指针直接使用点号访问字段，编译器会自动解引用，等价于 (*p).name；C 正确：(*p).name，先显式解引用再取字段，是标准的等价写法。B 错误：(&p).name，&p 得到的是"指向指针 p 的指针"（**T），并非结构体本身，不能继续对其使用字段访问。D 错误：p->name 是 C/C++ 的箭头语法，Go 不支持 -> 运算符。故正确选项为 AC。

### 2. 关于Go语言中panic和recover的使用，以下正确的是？（5分）

**A.** panic可以在任何地方引发，但recover只有在defer调用的函数中有效

**B.** recover用于终止panic的异常传递过程

**C.** panic无法被捕获，会直接导致程序崩溃

**D.** 使用panic和recover可以替代传统的错误处理方式

**正确答案：** AB　|　**我的答案：** AB　|　✅

**答案详解：** 该题考查 panic 与 recover 的使用机制。A 正确：panic 可以在程序的任何位置主动引发（调用 panic()），但 recover 只有在 defer 修饰的函数中调用才会生效，即 panic 发生后进入回退阶段执行延迟函数时，recover 才能截获 panic。B 正确：调用 recover() 会终止 panic 的异常传递过程，返回引发 panic 时传入的值，使程序恢复正常的执行流程。C 错误：panic 可以被 defer+recover 捕获，并非"无法被捕获、必崩溃"；只有未被 recover 的 panic 才会导致程序终止退出。D 错误：Go 官方明确主张使用返回 error 的方式处理常规错误，panic/recover 仅适用于程序无法继续运行的异常场景，不能替代常规错误处理。故正确选项为 AB。

### 3. 在 Go 语言中，关于数组（array）和切片（slice），以下说法正确的是？（5分）

**A.** 数组定义时必须指定长度，且长度是数组类型的一部分

**B.** 切片定义时不需要指定长度，其长度可以在运行时动态变化

**C.** 数组作为函数参数传递时，传递的是数组的副本，函数内对数组的修改不会影响原始数组

**D.** 切片作为函数参数传递时，传递的是切片结构体的副本，函数内对切片的修改会反映到原始切片上

**正确答案：** ABCD　|　**我的答案：** ABCD　|　✅

**答案详解：** 该题考查数组与切片的参数传递特性。A 正确：数组定义时必须指定长度（如 [5]int），且长度是数组类型的一部分，[2]int 与 [3]int 属于不同类型，互相不能赋值。B 正确：切片定义时无需指定长度，其长度（len）可以在运行时通过 append 等操作动态变化。C 正确：数组作为函数参数是值传递，形参是实参的完整副本，函数内对数组元素的修改不影响调用者的原数组（如需修改原数组要传数组指针）。D 正确：切片作为函数参数传递的是切片结构体（底层数组指针、length、capacity）的副本，但底层数组指针仍指向同一块数据，因此函数内修改切片的元素会反映到原始切片上（注意：append 若触发扩容则会改变切片的 length/capacity，不再影响原切片，但本题对元素修改的表述是正确的）。四句均正确，故选 ABCD。
