### 1. 团队项目平台中「用户管理」菜单仅管理员可见，这属于哪种权限控制？（5分）

> 背景
> 团队项目与任务管理平台（课件扩展）定义两种角色：
> 角色
> 权限
> admin
> 可管理所有项目、查看用户列表、管理项目成员
> member
> 仅看自己参与的项目与任务
> 需求摘要
> - 未登录不能访问业务页面；
> - 根据角色控制菜单和按钮显示（如「用户管理」仅 admin）；
> - 无权限操作时给予明确提示；
> - 后端仍须校验接口权限。
> 菜单按角色显示/隐藏属于？

**A.** 前端基于用户角色的 UI 权限控制（体验层），须与后端接口权限校验配合

**B.** 仅靠 CSS display:none 即可保证数据安全，无需后端参与

**C.** Hash 路由模式特有的安全机制

**D.** Whistle 代理规则的一部分

**正确答案：** A　|　**我的答案：** A　|　✅

### 3. 未登录直接访问 /users 应跳转登录页，完成后端联调还需满足什么？（5分）

### 7. 跨域 POST 带 Authorization 头时浏览器先发 OPTIONS 预检，预检失败的根本原因是？（5分）

> 背景
> 登录后请求用户列表，Network 面板先出现 OPTIONS /api/users，状态失败，真正的 GET 未发出。
> 现象摘要
> - 跨域且带自定义头（如 Authorization）时，浏览器可能先发 预检请求；
> - 后端需正确返回 Access-Control-Allow-Origin、Access-Control-Allow-Headers 等；
> - DevTools 中可见 OPTIONS 失败或响应头缺少 Access-Control-Allow-Origin。
> 预检失败导致业务请求被拦截，说明？

**A.** 后端未正确响应 CORS 预检

**B.** OPTIONS 请求必须用 POST 发送

**C.** 前端应删除 Authorization 头，CORS 与鉴权无关

**D.** 只有 HTTPS 才会触发预检，HTTP 不会

**正确答案：** A　|　**我的答案：** A　|　✅

**答案详解：** 核心是 CORS 预检流程：携带 Authorization 头或使用非简单方法时会先发 OPTIONS 预检，预检失败通常意味着服务端未正确响应 CORS 策略。✅ A 浏览器发出 OPTIONS 预检后，需要后端返回正确的 Access-Control-Allow-Origin、-Methods、-Headers（含 Authorization）等响应头且状态码为 2xx，预检失败的根本原因就是后端未正确响应。❌ B 预检请求本身就是 OPTIONS，不是用 POST 发送。❌ C Authorization 是业务鉴权所需，与 CORS 是两回事，删除它既不解决跨域也不利于鉴权。❌ D 预检与是否 HTTPS 无关，HTTP 下的跨域请求同样会触发。

> 
>

> 前端
> 后端

> http://localhost:5173

> http://localhost:5173
> http://127.0.0.1:8080
> ✅ 域名不同

### 10. Axios 请求拦截器自动添加 Authorization Bearer token，主要解决什么问题？（5分）

> 背景
> 登录成功后 token 存 localStorage，后续所有 API 请求需携带 Authorization: Bearer <token>。若每个 API 函数手写 header，容易遗漏。
> 封装代码（简化）
> 
> ```ts
> request.interceptors.request.use(config => {
>   const token = localStorage.getItem('token');
>   if (token) {
>     config.headers.Authorization = `Bearer ${token}`;
>   }
>   return config;
> });
> 
> 
> ```
> 现象摘要
> - 登录后访问 /api/users 自动带 token；
> - 401 时响应拦截器清除 token 并跳转登录页；
> - API 层只负责传输，业务逻辑放组件或 Hook。
> 请求拦截器统一注入 token 的主要价值是？

**A.** 让每个业务 API 函数不必重复写鉴权 Header

**B.** 替代后端 JWT 校验，前端带 token 就视为安全

**C.** 自动把 POST 改成 GET 以提升性能

**D.** 把 token 加密后存入 node_modules

**正确答案：** A　|　**我的答案：** A　|　✅

**答案详解：** 核心是请求拦截器的「统一注入」作用：在发送前集中处理公共逻辑。✅ A 拦截器统一为请求添加 Authorization: Bearer token，各业务 API 函数无需重复书写鉴权头，一次修改、处处生效。❌ B 拦截器只是前端行为，不能替代后端 JWT 校验，token 有效性必须由服务端验证。❌ C 拦截器不会改写请求方法类型。❌ D token 不会也不该加密存入 node_modules，业务凭证应安全存放（如 sessionStorage/localStorage/内存等）。
